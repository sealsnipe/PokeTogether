PokeTogether - Dokumentation

Übersicht

PokeTogether ist ein Pokémon-ähnliches Spiel mit Multiplayer-Funktionalität, das mit Python und Pygame entwickelt wurde. Spieler können sich in einer gemeinsamen Spielwelt bewegen und miteinander interagieren.

Installation

Methode 1: Ausführbare Datei (Windows)

Entpacke die ZIP-Datei in einen beliebigen Ordner
Starte das Spiel durch Doppelklick auf PokeTogether.exe oder start_game.bat

Methode 2: Quellcode (alle Plattformen)

Stelle sicher, dass Python 3.8 oder höher installiert ist
Klone das Repository oder lade es als ZIP-Datei herunter
Öffne eine Kommandozeile im Projektverzeichnis
Installiere die erforderlichen Pakete: 
pip install -r requirements.txt
Starte das Spiel: 
python src/main.py

Multiplayer-Modus

PokeTogether bietet einen integrierten Multiplayer-Modus, der es mehreren Spielern ermöglicht, sich in der Spielwelt zu sehen und zu interagieren.

Als Host (Server)

Starte das Spiel und wähle "New Game"
Drücke Enter oder die Start-Taste, um das Ingame-Menü zu öffnen
Wähle "MULTIPLAYER"
Wähle "HOST GAME", um eine Multiplayer-Session zu starten
Teile deine IP-Adresse mit anderen Spielern (siehe unten)

Als Client

Starte das Spiel und wähle "New Game"
Drücke Enter oder die Start-Taste, um das Ingame-Menü zu öffnen
Wähle "MULTIPLAYER"
Wähle "JOIN GAME", um einer Multiplayer-Session beizutreten
Gib die IP-Adresse des Hosts ein (standardmäßig wird "localhost" verwendet)

IP-Adresse herausfinden (für den Host)

Öffne eine Kommandozeile und gib ein:

  • Windows: ipconfig
  • Mac/Linux: ifconfig oder ip addr

Suche nach der IPv4-Adresse deines LAN-Adapters (in der Regel beginnt sie mit 192.168.x.x).

Hinweis: Stelle sicher, dass keine Firewall den Port 8765 blockiert, da dieser für die Multiplayer-Verbindung verwendet wird.

Fehlerbehebung

Verbindungsprobleme

  • Stelle sicher, dass keine Firewall den Port 8765 blockiert
  • Überprüfe, ob die IP-Adresse korrekt eingegeben wurde
  • Stelle sicher, dass Host und Client im selben Netzwerk sind

Spiel startet nicht

  • Überprüfe, ob alle erforderlichen Pakete installiert sind
  • Stelle sicher, dass Python 3.8 oder höher installiert ist
  • Überprüfe, ob alle Dateien im richtigen Verzeichnis sind

Steuerung funktioniert nicht

  • Überprüfe, ob ein Controller angeschlossen ist
  • Stelle sicher, dass der Controller von Pygame erkannt wird
  • Versuche, die Tastatur anstelle des Controllers zu verwenden

Technische Details

Architektur

PokeTogether verwendet eine Client-Server-Architektur für den Multiplayer-Modus:

  • Server: Verwaltet die Spieler-Sessions und synchronisiert die Spielerdaten
  • Client: Verbindet sich mit dem Server und sendet/empfängt Spielerdaten
  • WebSockets: Werden für die Echtzeit-Kommunikation zwischen Client und Server verwendet

Verwendete Technologien

  • Python: Programmiersprache
  • Pygame: Spiel-Engine
  • WebSockets: Netzwerkkommunikation
  • PyInstaller: Erstellung ausführbarer Dateien

Hauptkomponenten und ihre Zusammenhänge

Game-Klasse (src/game/core/game.py)

Die zentrale Klasse, die das gesamte Spiel steuert:

  • Initialisiert alle Komponenten (Spieler, Kamera, Karte, Menüs)
  • Implementiert die Hauptspielschleife (Game Loop)
  • Verwaltet die verschiedenen Spielzustände (Hauptmenü, Spielen, Pause, etc.)
  • Koordiniert die Eingabebehandlung und Rendering
  • Integriert die Multiplayer-Funktionalität
# Vereinfachter Ausschnitt aus game.py
class Game:
    def __init__(self):
        # Initialisierung der Komponenten
        self.screen = pygame.display.set_mode((800, 600))
        self.input_handler = InputHandler()
        self.player = Player("Red", 560, 448)
        self.camera = Camera(800, 600, 1120, 896)
        self.current_map = SimpleMap(35, 28, 32)

        # Multiplayer-Komponenten
        self.multiplayer_manager = MultiplayerManager()
        self.other_players = {}
        self.multiplayer_active = False

    def run(self):
        # Hauptspielschleife
        while self.running:
            self.handle_events()
            self.update()
            self.render()
            pygame.display.flip()
            self.clock.tick(60)

InputHandler-Klasse (src/game/core/input_handler.py)

Verarbeitet Tastatur- und Controller-Eingaben:

  • Erkennt angeschlossene Controller
  • Mappt Tasten und Controller-Buttons auf Aktionen
  • Stellt Methoden bereit, um den Zustand von Eingaben abzufragen
# Vereinfachter Ausschnitt aus input_handler.py
class InputHandler:
    def __init__(self):
        self.input_state = {}
        self.input_pressed = {}
        self.last_input_state = {}
        self.controllers = []

    def update(self):
        # Aktualisiert den Eingabezustand
        self.last_input_state = self.input_state.copy()
        self.input_pressed = {}

        # Tastatureingaben verarbeiten
        keys = pygame.key.get_pressed()
        if keys[pygame.K_UP]: self.input_state["up"] = True
        # ... weitere Tasten

        # Controller-Eingaben verarbeiten
        for controller in self.controllers:
            if controller.get_button(0): self.input_state["a"] = True
            # ... weitere Buttons

MultiplayerManager-Klasse (src/game/network/multiplayer_manager.py)

Koordiniert die Multiplayer-Funktionalität:

  • Verwaltet Server- und Client-Instanzen
  • Startet und stoppt Multiplayer-Sessions
  • Synchronisiert Spielerdaten zwischen Clients
# Vereinfachter Ausschnitt aus multiplayer_manager.py
class MultiplayerManager:
    def __init__(self):
        self.server = GameServer()
        self.client = GameClient()
        self.is_host = False
        self.local_player_data = {}

    def start_hosting(self, port=8765):
        # Server starten und als Host fungieren
        self.server.start()
        self.connect_to_session("localhost", port)
        self.is_host = True

    def connect_to_session(self, host, port=8765):
        # Mit einem Host verbinden
        self.client.connect(host, port)

    def update_player(self, player_data):
        # Spielerdaten aktualisieren und an Server senden
        self.local_player_data = player_data
        self.client.send_player_update(player_data)

Server- und Client-Klassen (src/game/network/server.py, src/game/network/client.py)

Implementieren die Netzwerkkommunikation:

  • GameServer: Verwaltet Verbindungen und Broadcast von Spielerdaten
  • GameClient: Verbindet sich mit dem Server und verarbeitet eingehende Nachrichten

Datenfluss im Multiplayer-Modus

  1. Der Host startet eine Multiplayer-Session mit multiplayer_manager.start_hosting()
  2. Clients verbinden sich mit multiplayer_manager.connect_to_session(host_ip)
  3. Bei jeder Aktualisierung sendet jeder Client seine Spielerdaten (Position, Richtung, etc.) an den Server
  4. Der Server broadcastet diese Daten an alle anderen verbundenen Clients
  5. Jeder Client rendert die anderen Spieler basierend auf den empfangenen Daten

Rendering-Pipeline

Der Rendering-Prozess folgt diesem Ablauf:

  1. Die Karte wird gerendert (Hintergrund, Terrain, Objekte)
  2. Der lokale Spieler wird gerendert
  3. Andere Spieler werden gerendert (im Multiplayer-Modus)
  4. UI-Elemente werden über allem anderen gerendert
# Vereinfachter Ausschnitt aus game.py (render-Methode)
def render(self):
    # Bildschirm löschen
    self.screen.fill((0, 0, 0))

    if self.current_state == self.states["PLAYING"]:
        # Karte rendern
        self.current_map.render(self.screen, self.camera.get_offset())

        # Spieler rendern
        self.player.render(self.screen, self.camera.get_offset())

        # Andere Spieler rendern (Multiplayer)
        if self.multiplayer_active:
            self._render_other_players()

    # UI-Elemente rendern je nach Spielzustand
    if self.current_state == self.states["MAIN_MENU"]:
        self.main_menu.render()
    elif self.current_state == self.states["INGAME_MENU"]:
        self.ingame_menu.render()

Implementierungsdetails

Eingabebehandlung

Die Eingabebehandlung ist so konzipiert, dass sie sowohl Tastatur- als auch Controller-Eingaben unterstützt. Der InputHandler abstrahiert die physischen Eingaben in logische Aktionen wie "up", "down", "a", "b", etc.

Besonders wichtig ist die Behandlung von Eingaben in verschiedenen Spielzuständen:

  • Im Spielzustand steuern die Eingaben den Spieler
  • In Menüs navigieren die Eingaben durch die Menüoptionen
  • Beim Wechsel zwischen Zuständen müssen Eingaben zurückgesetzt werden, um unerwünschte Aktionen zu vermeiden

Multiplayer-Synchronisation

Die Multiplayer-Implementierung verwendet ein einfaches Client-Server-Modell mit WebSockets für die Echtzeit-Kommunikation. Jeder Client sendet regelmäßig seine Spielerdaten an den Server, der diese dann an alle anderen Clients weiterleitet.

Das Protokoll verwendet JSON-formatierte Nachrichten mit folgenden Typen:

  • welcome: Begrüßungsnachricht vom Server mit Client-ID und aktuellen Spielern
  • player_update: Aktualisierung der Spielerdaten (Position, Richtung, etc.)
  • player_disconnected: Benachrichtigung, wenn ein Spieler die Session verlässt
  • chat_message: Chat-Nachrichten zwischen Spielern

Kamera und Rendering

Die Kamera folgt dem Spieler und sorgt dafür, dass er immer im sichtbaren Bereich bleibt. Sie berechnet einen Offset, der auf alle gerenderten Objekte angewendet wird, um die korrekte Position auf dem Bildschirm zu bestimmen. 

# Vereinfachter Ausschnitt aus camera.py
class Camera:
    def __init__(self, width, height, map_width, map_height, zoom=1.0):
        self.width = width
        self.height = height
        self.map_width = map_width
        self.map_height = map_height
        self.zoom = zoom
        self.x = 0
        self.y = 0

    def update(self, target_x, target_y):
        # Kamera auf Spieler zentrieren
        self.x = target_x - self.width / (2 * self.zoom)
        self.y = target_y - self.height / (2 * self.zoom)

        # Kamera innerhalb der Kartengrenzen halten
        self.x = max(0, min(self.x, self.map_width - self.width / self.zoom))
        self.y = max(0, min(self.y, self.map_height - self.height / self.zoom))

    def get_offset(self):
        # Offset für Rendering berechnen
        return (-self.x * self.zoom, -self.y * self.zoom)
